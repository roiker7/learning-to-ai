## 배운 것
- `for line in file`은 한 줄씩 읽고, `readlines()`는 전부 리스트로 메모리에 올린다. 파일이 메모리보다 크면 `readlines()`는 실패한다. 결과가 빨라지는 게 아니라 **가능해지는** 것
- `strip()`은 양 끝의 공백·줄바꿈을 **지운다**(공백으로 바꾸지 않음). `rstrip("\n")`은 끝의 줄바꿈만 지운다
- 값을 바꾼 뒤에는 바뀐 값으로 비교해야 한다(`strip()` 뒤의 빈 줄은 `''`)
- `A in B`는 "A가 B 안에 있나". 찾는 것이 앞
- 제너레이터를 연결하면 값 하나가 끝까지 지나간 뒤 다음 값을 꺼낸다. 중간을 `list(...)`로 감싸면 결과는 같지만 전부 만든 뒤에야 다음 단계가 시작되고 메모리에 쌓인다
- 오류 메시지는 맨 아래 줄부터 읽고, 오류가 난 곳과 원인이 있는 곳이 다를 수 있다
- `print(repr(x))`로 공백과 줄바꿈까지 보이게 값을 확인할 수 있다

## 막힌 것

### 배운 것
- `json.dumps`는 딕셔너리 → 글자(쓸 때), `json.loads`는 글자 → 딕셔너리(읽을 때). `loads`에는 반드시 글자를 넣는다. `ensure_ascii`는 기본이 `True`
- 잘못된 JSON은 `JSONDecodeError`(ValueError의 한 종류)
- CSV는 `csv.DictReader`로 읽고 값은 모두 글자. `fieldnames`는 헤더 리스트, 각 행은 딕셔너리
- CSV 파일은 `encoding="utf-8-sig"`(엑셀 BOM)와 `newline=""`(줄바꿈 중복 방지)로 연다
- 읽을 때 `for`는 파일을, 쓸 때 `for`는 데이터를 돈다
- JSONL은 프로그램용(숫자·목록 그대로), CSV는 사람용(엑셀)

### 막힌 것
- `dumps`/`loads` 방향을 반대로 답함, `fieldnames`를 딕셔너리로 답함 → 설명 후 다른 문제로 맞힘
- 종합에서 읽기와 쓰기를 두 단계로 나눠 생각함, `return`으로 첫 줄에서 끝남, 빈 리스트에 `append`로 모으기, `append(key)` vs `append(a[key])` → 지쳐서인 것 같다는 데 동의

### 생각
- JSONL과 CSV의 차이는 정말 중요한 개념이라고 느낌
- JSONL→CSV 변환 자체는 실무에서 흔하지 않은데 필요한가 의문 → '읽고→바꾸고→쓰기' 흐름이 중요하다는 설명을 들었지만, 다시 쓰기까지는 과하다고 판단
