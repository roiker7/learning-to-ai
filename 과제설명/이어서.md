## AI가 지켜야 할 진행 방식 (중요)
- 목표는 완성된 결과물이 아니라 **학습자의 역량 강화**.
- **전체 코드를 대신 작성하지 말 것.** 개념 설명 → 가이드 → 질문으로 생각 유도 → 학습자가 작성 → 리뷰 순서로 진행.
- 작은 예시 코드는 괜찮지만(가계부와 무관한 예시 권장: `greet.py`, `pet.py` 등), 학습자가 바로 복사해 쓸 수 있는 완성 구현은 주지 않음.
- 학습자는 파이썬 기초는 알지만 **argparse, 객체/메서드 패턴, 명령줄 인자 방식은 처음**. 용어를 처음 쓸 때는 쉽게 풀어서 설명하고, 앞에서 쓴 예시를 언급할 때는 다시 보여줄 것 (지난 세션에서 "pet 예시가 뭔지 모르겠다"는 반응이 있었음).
- 설명 후에는 "직접 실행해 보고 결과 알려주기" + "먼저 예상해 보기" 질문으로 마무리하면 반응이 좋았음.

## 지금까지 학습한 개념
### 1일차 (설계)
1. **JSON과 JSONL의 차이**: JSON은 전체를 읽어야 해석 가능, JSONL은 줄 단위로 처리 가능 → 스트리밍 조건에 맞음.
2. **tags와 category**: category는 1개, 필수, 등록된 목록에서만 선택 / tags는 0개 이상의 자유로운 꼬리표 리스트(검색용).
3. **첫 실행에 카테고리가 필요한 이유**: `add`는 등록된 카테고리만 허용하므로, 카테고리가 없으면 거래를 추가할 수 없음.
4. **계층이 필요한 이유**: "입력 → 행동 → 저장" 흐름이 CLI → Service → Repository (+ Model)에 대응. 중복 제거, 저장 방식 교체 쉬움, 버그 위치를 빨리 좁힐 수 있음. 명세상 3개 이상 모듈 분리 필수.
5. **실행 방식**: 메뉴 반복(`input()`으로 명령 선택)이 아니라 **명령 한 번 = 실행 한 번** (`argparse`). `input()`은 `add`/`update`의 대화형 입력에서만 사용.
6. **검증 설계**: 검사 로직은 입력 코드와 분리된 함수 하나로 두고, 틀렸을 때의 반응(재입력/오류 종료/건너뛰기)은 호출하는 쪽이 정함.

### 2일차 (실행 진입점과 argparse)
7. **`python -m 패키지`**: 패키지(폴더)를 찾아 그 안의 `__main__.py`를 실행. `python main.py`(파일 하나 실행)와 다름 → 기존 `main.py`는 삭제함.
8. **`__init__.py`**: "이 폴더는 패키지"라는 표시. import할 때 실행됨(`__main__.py`는 실행할 때). 이 프로젝트에선 비워 둬도 됨. 파일 이름은 밑줄 두 개씩.
9. **`sys.argv`**: 터미널 입력을 띄어쓰기로 나눈 **문자열 리스트**. `[0]`은 실행된 파일(`-m`이면 `__main__.py`의 전체 경로), 사용자 입력은 `[1]`부터. 숫자도 문자열(`'5'`)로 들어옴. 직접 출력해서 확인함.
10. **argparse 기본**: `sys.argv`를 해석해 주는 도구("주문서 양식" 비유). 3단계 패턴 ① `ArgumentParser()`로 만들기 ② `add_argument()`로 설정 ③ `parse_args()`로 실행. 결과는 `Namespace`이고 `args.이름`으로 꺼냄.
    - ③을 빠뜨려서 `--help`가 아무것도 안 나오는 경험을 함 → "에러가 없다 ≠ 원하는 대로 동작한다"
    - `--help`를 만나면 `parse_args()`가 도움말 출력 후 바로 종료 → 그 뒤 `print(args)`는 실행 안 됨
11. **정해진 이름 vs 자유로운 이름**: `ArgumentParser`, `description`, `add_argument` 등은 라이브러리가 정한 이름(대소문자 정확히). 변수 이름, 설명 문구, 옵션 이름은 자유.
12. **객체 → 메서드 패턴**: `parser.add_argument(...)`는 `names.append(...)`와 같은 모양. 파이썬 라이브러리 대부분이 이 형태.
13. **`help` / `description`**: `help`는 `--help` 목록에서 각 항목 옆 한 줄 설명, `description`은 맨 위 긴 설명. 명세의 "모든 명령은 `--help` 지원" 조건과 연결됨.
14. **`type=int`, `default`**: 문자열을 정수로 변환(실패 시 argparse가 오류), 옵션 생략 시 기본값.
15. **옵션(`--add`) vs 하위 명령(`add`)**: 처음엔 add/list/search를 옵션으로 만들었다가 문제점 발견(여러 개 동시 입력, 명령별 옵션 구분 불가, 값을 꼭 넣어야 함) → subparsers로 변경.
16. **subparsers 동작**: 명령 자리는 하나뿐, 그 뒤는 전부 그 명령의 옵션으로 취급 → 명령 두 개 동시 입력은 argparse가 자동으로 막음. 각 명령은 **`add_argument`로 등록한 옵션만** 받음 (`add --limit 2`, `list --list 집가기` → `unrecognized arguments`). 하위 명령은 `--` 없이 단어로 씀(`--list 집가기`라고 치면 '집가기'가 명령 자리로 들어가 `invalid choice` 오류).
17. **`action="store_true"`**: 값 없이 켜짐/꺼짐만 필요한 옵션(플래그). 개념만 설명, 아직 사용 안 함.
