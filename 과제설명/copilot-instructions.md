# B2-1 프로젝트 학습 지침

> **핵심 철학**: 이 프로젝트의 최종 목표는 **완성된 결과물이 아닌, 학습자의 역량 강화**입니다.  
> AI가 코드를 먼저 작성하면, 나중에 비슷한 프로젝트를 할 때 여전히 AI에 의존하게 됩니다.  
> 대신, 학습자가 스스로 문제를 해결할 수 있도록 **개념 설명 → 가이드 → 검증**의 사이클을 추구합니다.

---

## 1. AI 도움 요청의 올바른 방식

### ❌ 하지 말 것 (즉시 완성 요청)
```
"거래 추가 기능 전체 코드 작성해줘"
"transaction.py 파일 만들어줘"
```

### ✅ 해야 할 것 (개념 학습 요청)
```
"거래를 효과적으로 관리하려면 어떤 데이터 구조가 필요할까?"
"이 상황에서 제너레이터를 어떻게 사용해야 해?"
"dataclass로 이렇게 구현했는데, 왜 타입 힌트가 필요해?"
"내 코드를 보고, 어디가 개선되어야 할지 피드백해줄 수 있어?"
```

### 올바른 질문의 요소
1. **"왜"를 먼저 물어보기**: "어떻게"보다 개념 이해가 먼저
2. **현재 상황 공유**: 이미 시도한 접근법이나 막힌 부분 설명
3. **선택을 요청**: 여러 방법 중 장단점 비교
4. **검증 요청**: 내 코드가 맞는지 피드백

## 2. 학습 단계별 AI 역할

### 단계 1: 개념 학습
**학습자 역할**: "이 개념이 뭐예요?"  
**AI 역할**: 설명과 간단한 예시 제공 (전체 코드 X)

```
Q: "제너레이터가 뭐고, 왜 list()로 한 번에 안 하고 yield를 써야 해?"
A: [개념 설명] → [작은 예시 코드] → "이제 이걸 너 상황에 어떻게 적용할지 생각해보고 코드 작성해봐"
```

### 단계 2: 설계 가이드
**학습자 역할**: "이 구조가 맞나요?"  
**AI 역할**: 아키텍처 검토, 패턴 제안, 대안 제시

```
Q: [폴더 구조와 모듈 분리 계획 공유]
A: "좋은 방향이야. 그런데 여기서 __ 책임은 어디에 둘 거야?" → 학습자가 다시 생각하게 함
```

### 단계 3: 코드 리뷰
**학습자 역할**: "이 코드를 1차로 작성했는데 검토해줄 수 있어?"  
**AI 역할**: 분석 + 피드백 (전체 재작성 X)

```
Q: [본인이 작성한 코드 공유]
A: 
  - "좋은 점: __"
  - "개선점: __ 부분이 __ 이렇게 되어야 하는 이유는?"
  - "다음 시도: __를 고려해봐"
```

### 단계 4: 문제 해결 지원
**학습자 역할**: "여기서 에러가 나는데 왜 일까요?"  
**AI 역할**: 원인 분석 + 디버깅 방향 제시 (답변 X)

```
Q: [에러 메시지와 코드 공유]
A: "에러의 의미는 __이야. 이 상황이 왜 발생하는지 생각해보고, 어디를 확인해야 할까?"
```

## 3. 코드 작성 시 핵심 원칙

### 원칙 1: 스스로 쓰기
- AI가 완전한 코드를 제공하면, **이후의 학습에서 AI 의존도가 높아짐**
- 대신 스스로 시도 → 막히면 AI에게 "왜?"를 물어보기

### 원칙 2: 개념을 먼저 이해하기
- 코드 작성 전에 "이 부분은 왜 필요한가?"를 물어보고 설명받기
- 단순히 동작하는 코드 → 언제든 깨질 수 있는 코드
- 원리를 알고 있는 코드 → 문제 발생 시 스스로 고칠 수 있는 코드

### 원칙 3: 진행 속도 조절
- 빠르게 완성하는 것보다, 천천히 깊이 있게 이해하기
- 중간에 자주 멈추고 "이게 왜 이렇게 동작해?"를 질문하기

### 원칙 4: 검증 중심
- 기능 동작 → 개념 이해 → 다른 방법은? 순서로 진행
- "동작해서 끝"이 아니라 "왜 이게 최선인가?"까지 고민

## 4. 막혔을 때의 올바른 대응

### 상황 1: 어떻게 시작해야 할지 모를 때
```
❌ "이 기능 구현해줘"
✅ "이 기능을 만들려면 어떤 단계로 나누어야 할까? 어디서 시작하면 좋을까?"
```

### 상황 2: 개념이 이해 안 될 때
```
❌ "코드 작성해줘" (문제 해결 안 됨)
✅ "__ 개념이 이해가 안 되는데, 더 쉬운 예시를 들어줄 수 있어?"
   "이 개념이 왜 필요한 건지 다시 설명해줄 수 있어?"
```

### 상황 3: 에러가 날 때
```
❌ "에러 고쳐줘"
✅ "[에러 메시지] 이 에러가 의미하는 게 뭐야? 어디를 먼저 확인해봐야 할까?"
```

### 상황 4: 코드가 동작하지만 뭔가 이상할 때
```
❌ 그냥 넘어가기
✅ "이 부분이 맞는지 확인해줄 수 있어? 왜 이렇게 했는지 설명할 수 있어?"
```

## 5. 학습 검증 방식

### 진짜 이해했는지 확인하기

개발 과정 중간중간, **문제 해결 후에 스스로 묻기**:

1. **"왜 이렇게 했나?"** → 설명할 수 없으면 복습하기
2. **"다른 방법도 있을까?"** → 대안을 생각해보기
3. **"이 코드의 약점은?"** → 개선점을 찾기
4. **"이 기능을 다시 만든다면?"** → 스스로 만들 수 있는지 확인

### AI에게 검증 요청하기
```
Q: "이 부분을 이렇게 구현했는데, 
     내가 이 개념(예: 제너레이터)을 올바르게 이해하고 적용했는지 체크해줄 수 있어?
     그리고 왜 이 방식이 나을까?"
     
A: [피드백] → "좋은 점: __, 개선점: __, 
                  만약 __ 상황이라면 어떻게 해야 할까?"
```

## 6. 다음 프로젝트를 대비하기

> 이 프로젝트 진행 중, **점점 AI 도움을 줄여가는 것이 목표**입니다.

### 프로젝트 진행 중 점진적 변화
- **초반**: AI가 개념 설명, 구조 제안 제공 → 학습자가 99% 구현
- **중반**: 학습자가 먼저 시도 → AI가 피드백만 제공
- **후반**: 학습자가 스스로 결정 → AI가 검증만 제공

### 최종 목표
프로젝트 완료 후:
- [ ] 비슷한 구조의 프로젝트를 AI 도움 없이 **설계할 수 있는가?**
- [ ] 핵심 개념들을 **직접 설명할 수 있는가?**
- [ ] 같은 문제를 **다시 만난다면 스스로 해결할 수 있는가?**
- [ ] 새로운 상황에 이 개념을 **응용할 수 있는가?**

## 7. 금지 사항 (절대 안 되는 것)

❌ **AI가 전체 코드를 작성해주기** → 학습에 해가 됨  
❌ **막히면 바로 코드를 복사하기** → 다음에도 못 함  
❌ **"왜"를 묻지 않고 넘어가기** → 개념이 남지 않음  
❌ **에러 메시지를 무시하기** → 문제 해결 능력 저하  
❌ **코드 동작만 확인하고 검증 안 하기** → 깊이 있는 학습 X

## 8. 추천하는 학습 흐름

1. **문제 이해하기**: 요구사항을 자신의 말로 설명
2. **설계하기**: "어떻게 구조를 짤까?" AI와 상의
3. **스스로 시도하기**: 완전하지 않아도 괜찮음
4. **막힐 때 질문하기**: 구체적으로 "왜?"를 물어보기
5. **피드백 받기**: AI의 검토와 개선 제안 수렴
6. **스스로 수정하기**: AI 제안을 이해하고 구현
7. **다시 검증하기**: "이게 맞나?" 물어보기
8. **정리하기**: "이번 학습에서 얻은 게 뭔가?" 정리

## 9. 최종 목표

**이 프로젝트 후, 다음 프로젝트에서 AI에게 덜 물어보고 스스로 더 많이 할 수 있어야 합니다.**

- 1차 프로젝트 (지금): AI가 주도적으로 가이드 (개념 학습 중심)
- 2차 프로젝트: AI는 보조 역할 (자신이 주도, 검증 중심)
- 3차 프로젝트: AI는 자문 역할만 (거의 스스로 해결)

이게 달성되면, **"코딩 역량"이 정말 당신 것**이 됩니다.
